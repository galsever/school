# School

Personal school hub at school.galsever.com (HTL Spengergasse): Microsoft Teams client, school mail, assignments, the WebUntis absences (former excuses app) and the school Moodle (former moodle-mcp). Read README.md and docs/API.md first, and mastermem `project:school` (older notes: `project:teams`, `project:excuses`).

- Server `server/school/` (FastAPI): `main.py` routes, `ms.py` device login and tokens, `upstream.py` chat service, Graph and Assignments calls mapped to API shapes, `mcp.py` the MCP at /api/mcp.
- Absences: `untis.py` WebUntis client, `absences.py` model, stats, storage and sync, `letter.py` the Entschuldigung PDF, `absences_api.py` routes and MCP tools, `timetable.py` MCP tools timetable, exams, homework (former untis-mcp). How it works and how to test without WebUntis: docs/ABSENCES.md. Tests: `cd server && ../.venv/bin/python -m pytest tests`.
- WebUntis: a rejected login blocks syncing until the login is changed in Settings. Never retry a login in a loop or test with guessed passwords: Spengergasse locks accounts.
- Moodle (docs/MOODLE.md): `moodle.py` client (login, cache, files, submissions, choices, publication via the website session), `moodle_api.py` routes, uploads, text extraction and the `moodle_*` MCP tools; web `routes/moodle*.tsx`. `mod_assign_save_submission` replaces all plugin data: keep going through `moodle.save_submission`. Never log a Moodle file address (it carries the key). Do not reorder or hide course content to simplify: he wants it to look like Moodle, simpler only in the chrome.
- Books (docs/BOOKS.md): `books.py` digi4school client (login, shelf, LTI hops, download, text placement, FTS5 index), `books_api.py` routes and `books_*` MCP tools; web `routes/books.tsx`, `lib/books.ts`. Page SVGs come from digi4school: serve them only with the CSP headers in `books_api.py`. Never copy book pages or text into commits, docs or memories. A rejected digi4school login is never retried.
- `mail.py` school Outlook (docs/MAIL.md: conversation view, rendering, compose, testing without sending), `prefs.py` own team and channel names and hidden flags (`DATA_DIR/prefs.json`).
- Website `web/` (Vite, React, shadcn, TanStack). `npm run build` must pass. Message HTML from Teams is untrusted: always through `safeHtml` (DOMPurify). Mail bodies through `mailHtml` (same file, docs/MAIL.md); its `styled` output (sender's CSS kept) goes only into `MailFrame` (sandboxed iframe with CSP in `routes/mail.tsx`), never into the page. Mail writing goes through `/api/mail/compose` (`mail.compose`). Team and channel logic uses `original` (Microsoft's name), display uses `name`.
- A new route or changed shape goes into docs/API.md in the same commit.
- Deploy: push to `main`; doco-cd on ghs runs `docker compose up -d --build`. Routing and login live in personal-infra (`apps/school-hub`, `hosts/ghs`).
- Never test turn-in, send or delete against real classes or chats without asking: it is the real school account.
